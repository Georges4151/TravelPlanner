## 1. 项目背景与目标

### 1.1 项目背景
随着旅游业的快速发展，游客在旅行规划过程中面临诸多痛点：
- 景点人流量大，排队时间长
- 行程规划复杂，信息分散
- 缺乏智能化的行程建议
- 团队协作困难

### 1.2 项目目标
打造一款**错峰旅行规划助手**应用，帮助用户：
- ✅ 智能规划行程，避开人流高峰
- ✅ 一站式管理景点、酒店、餐厅、交通
- ✅ AI智能生成行李清单
- ✅ 实时提醒不错过任何重要事项
- ✅ 支持多人协作，共同规划旅程

### 1.3 核心价值主张
- **错峰出行**：基于大数据的人流预测，推荐最佳游览时间
- **智能规划**：AI驱动的个性化行程和清单生成
- **便捷协作**：二维码分享、实时同步
- **贴心提醒**：多渠道提醒（应用内通知、短信）

## 5. 核心功能实现

### 5.1 智能行李清单生成

**实现位置**：`ChecklistActivity.java`

**功能特点**：
1. **AI智能生成**
   - 调用 DeepSeek AI API
   - 根据行程信息（目的地、天数、人数、风格）生成
   - 结合天气信息优化清单内容
   
2. **本地规则生成**
   - 不依赖AI，离线可用
   - 支持多种旅行类型：休闲、商务、徒步、亲子、海滩、滑雪
   - 根据温度范围调整衣物建议
   - 根据天气状况添加特殊物品

3. **行程绑定**
   - 清单与行程关联存储
   - 支持查看某行程的所有清单
   - 追加模式保存，避免覆盖

**关键代码逻辑**：
```java
// AI生成流程
1. 获取用户选择的行程信息
2. 查询目的地天气
3. 构建AI提示词（包含行程+天气）
4. 调用 DeepSeek API
5. 解析返回的JSON格式清单
6. 显示并保存到数据库

// 本地生成流程
1. 获取用户输入的参数
2. 根据旅行类型加载基础物品列表
3. 根据温度添加衣物
4. 根据天气添加特殊物品
5. 显示并保存到数据库
```

### 5.2 应用内通知提醒

**实现位置**：
- `TripReminderActivity.java` - 提醒管理界面
- `ReminderReceiver.java` - 广播接收器

**功能特点**：
1. **精确闹钟**
   - 使用 `AlarmManager.setExactAndAllowWhileIdle()`
   - 即使在低电耗模式下也能准时触发
   - Android 12+ 自动申请精确闹钟权限

2. **通知渠道**
   - Android 8.0+ 使用 NotificationChannel
   - 高优先级通知
   - 支持振动和灯光

3. **完整生命周期管理**
   - 添加提醒时设置闹钟
   - 开关控制闹钟启停
   - 删除时取消闹钟和通知

**实现原理**：
```
用户添加提醒 → 解析时间 → 创建PendingIntent 
           → 设置AlarmManager → 到达时间触发
           → ReminderReceiver接收 → 创建Notification
           → 显示通知栏通知 → 点击跳转到提醒页面
```

### 5.3 多人协作功能

**实现位置**：`CollaborationActivity.java`

**功能特点**：
1. **二维码分享**
   - 使用 ZXing 库生成二维码
   - 包含唯一的分享码
   - 扫描即可加入协作

2. **链接分享**
   - 生成分享链接
   - 一键复制到剪贴板
   - 支持通过社交应用分享

3. **权限管理**

   - 读写权限：可编辑行程

### 5.4 错峰出行建议

**实现位置**：景点搜索和详情页面

**数据来源**：
- 高德地图 POI 搜索

## 9. 关键技术难点与解决方案

### 9.1 难点一：高德API返回数据格式不一致

**问题描述**：
高德地图POI搜索API返回的某些字段类型不固定，例如 `address` 字段有时是字符串，有时是数组。

**解决方案**：
创建自定义Gson反序列化器 `StringOrListDeserializer`：

```java
public class StringOrListDeserializer implements JsonDeserializer<String> {
    @Override
    public String deserialize(JsonElement json, Type typeOfT, 
                             JsonDeserializationContext context) throws JsonParseException {
        if (json.isJsonArray()) {
            StringBuilder sb = new StringBuilder();
            for (JsonElement element : json.getAsJsonArray()) {
                if (sb.length() > 0) sb.append(", ");
                sb.append(element.getAsString());
            }
            return sb.toString();
        } else if (json.isJsonPrimitive()) {
            return json.getAsString();
        }
        return "";
    }
}
```

**应用位置**：
- `biz_type` 字段
- `business_area` 字段
- `address` 字段

### 9.2 难点二：精确闹钟权限管理（Android 12+）

**问题描述**：
Android 12 (API 31+) 引入了精确闹钟限制，需要用户手动授权。

**解决方案**：
```java
private void scheduleReminder(ReminderItem item) {
    // 检查是否有精确闹钟权限
    if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.S) {
        if (!alarmManager.canScheduleExactAlarms()) {
            // 引导用户去设置页面授权
            Intent intent = new Intent(Settings.ACTION_REQUEST_SCHEDULE_EXACT_ALARM);
            startActivity(intent);
            return;
        }
    }
    
    // 设置精确闹钟
    alarmManager.setExactAndAllowWhileIdle(
        AlarmManager.RTC_WAKEUP,
        triggerTimeMillis,
        pendingIntent
    );
}
```

### 9.3 难点三：AI生成的JSON解析容错

**问题描述**：
DeepSeek AI 返回的内容可能不是标准JSON格式，或者格式不符合预期。

**解决方案**：
```java
try {
    // 尝试从AI响应中提取JSON
    String content = extractJsonFromResponse(responseBody);
    
    // 解析JSON数组
    JSONArray jsonArray = new JSONArray(content);
    
    for (int i = 0; i < jsonArray.length(); i++) {
        JSONObject obj = jsonArray.getJSONObject(i);
        String name = obj.getString("name");
        String category = obj.optString("category", "其他");
        
        allItems.add(new ChecklistItem(name, category));
    }
    
    success = true;
} catch (Exception e) {
    Log.e(TAG, "AI Parse Error", e);
    success = false;
}

// 如果AI解析失败，降级为本地规则
if (!success) {
    generateLocalList(...);
}
```

### 9.4 难点四：Room数据库线程安全

**问题描述**：
Room 数据库不允许在主线程执行查询操作，否则会抛出异常。

**解决方案**：
使用 Executor 在后台线程执行数据库操作：

```java
Executor executor = Executors.newSingleThreadExecutor();
Handler handler = new Handler(Looper.getMainLooper());

// 后台线程查询
executor.execute(() -> {
    List<ItineraryEntity> itineraries = itineraryDao.getAll();
    
    // 主线程更新UI
    handler.post(() -> {
        adapter.setData(itineraries);
    });
});
```

### 9.5 难点五：行李清单覆盖问题

**问题描述**：
多次生成或保存清单时，新清单会覆盖旧清单。

**解决方案**：
改为追加模式，只添加不存在的新物品：

```java
private void saveAllToDatabase(Long targetItineraryId) {
    // 获取已存在的物品
    List<ChecklistItemEntity> existingItems = checklistDao.getByItineraryId(targetItineraryId);
    
    // 构建已存在物品名称集合
    List<String> existingNames = existingItems.stream()
        .map(ChecklistItemEntity::getItemName)
        .filter(name -> name != null)
        .collect(Collectors.toList());
    
    // 只添加新物品
    for (ChecklistItem item : allItems) {
        if (!existingNames.contains(item.getName())) {
            ChecklistItemEntity entity = convertToEntity(item, targetItineraryId);
            checklistDao.insert(entity);
        }
    }
}
```
